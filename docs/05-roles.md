# 角色任务书

> 「角色任务书」＝每个会话角色一份 markdown 文件，**机器读**（bootstrap / 域桥按格式渲染成新会话的首条消息）＋ **人也能读**（就是一段干净的开场词）。
> 目录：`{体系根}/templates/roles/`，契约唯一源＝该目录下的 `README.md`。路径占位符与角色自己的槽位是两回事，见 `paths.md`。

## 1. 为什么要机读

**问题**：以前"以什么身份开工"靠**人复制粘贴**一段开场词（`{体系根}/templates/会话开场提示词.md`），靠人不漏段——而"以什么身份开工"恰恰是最不该走样的一段。

**做法**：把同一件事变成**插件能读的唯一源**。于是：

- 建会话的一方不用再记口令，只给一个 `role` 名字；
- AI 不会因为少贴一段而跑偏；
- 提示词文件降级为**人读说明 ＋ 兜底粘贴版**，内容以 `roles/` 为准——**改角色口径先改 `roles/`**。

**代价（如实）**：格式受约束（头块 ＋ 固定三段 ＋ 槽位），写起来不如自由散文舒服；这是换"不走样"付的价。

**两者的分工**（`roles/README.md` 原文口径）：

| | `templates/roles/` | `templates/会话开场提示词.md` |
|---|---|---|
| 角色 | **唯一源**（机器读的那份） | 人读说明 ＋ 兜底粘贴版 |
| 覆盖什么 | 角色口径（管什么 / 不管什么） | 设计理由、粘贴仪式 |
| 谁改谁 | **先改这里** | 改完回看对应段要不要同步 |

**bootstrap 怎么用它**：工具的 `role` 参数默认 `project-main`，读 `templates/roles/<role>.md` 渲染成首条消息；**文件不存在就如实报 `missing-role-template`，不许现编任务书**。（该 bootstrap 工具目前**只有规格、代码未实现**，见 `06-limitations.md`。）

## 2. 格式契约（schema 1）

```markdown
ROLE: <role-id>
SCHEMA: 1
SLOTS: <槽位1>, <槽位2>
---

## 角色
一段话：这是什么角色、管什么、不管什么。

## 开场
可直接作为新会话**首条消息**的开场白（第一人称对 AI 说）；槽位写 {槽位名}。

## 规则
- 一条一行，3~6 条
```

**解析约定（实现方照此写，别自创）**：

| 约定 | 说明 |
|---|---|
| **头块** | 文件开头到第一条 `---` 行；每行 `KEY: value`；键只有 `ROLE` / `SCHEMA` / `SLOTS` |
| **段** | `## 角色` / `## 开场` / `## 规则`，按 `## ` 切；**只认这三段**，其余段落忽略 |
| **规则段** | 每行以 `- ` 开头为一条；其他行归入上一条或忽略 |
| **槽位** | `{名字}`，**只能**用 `SLOTS` 里声明过的名字；未声明的按字面保留 |
| **渲染** | 输出**纯文本**：`【角色】…` ＋ 换行 ＋ `【开场】…` ＋ 换行 ＋ `【规则】` ＋ 每条一行 `- …` |
| **缺失** | 角色文件不存在／三段缺段 ⇒ **如实报 `missing-role-template`**，不许现编任务书 |

**为什么渲染成纯文本、不依赖 markdown 结构**：插件投递过去的是一条**纯文本消息**（v4 用户消息），到了对面不保证还按 markdown 解析——所以结构必须由渲染结果自己带（`【角色】`/`【开场】`/`【规则】` 就是它的骨架）。

**写文件时要避开的四个坑**（从"人读提示词"抽成机读时逐条实测）：

| 坑 | 处理 |
|---|---|
| 三段字段名本来不齐（同一个位置有人写【开场】、有人写【任务】、有人写【职责】） | 统一成 `## 角色` / `## 开场` / `## 规则` 三段，逐段归一 |
| 槽位写法是尖括号 `<项目名>`，与机读要求的 `{占位符}` 不同 | 一律改 `{占位符}`（无脚本引用旧写法，替换零风险） |
| 体系根被逐字硬编码 | 统一写 `{体系根}`，换机只替换一个前缀 |
| 原文自称的"场景段"个数是错的 | 以实测为准（提示词文件 160 行 / 8 个 `##` / 6 个场景段），别照抄自述数字 |

## 3. 角色清单（当前 8 份）

| 文件 | 角色 id | 一句话职责 | 谁在用 |
|---|---|---|---|
| `project-main.md` | `project-main` | 项目主会话：统筹、派发、合并 | bootstrap 建的那 1 条项目主会话（按规格；bootstrap 代码未实现） |
| `project-init-main.md` | `project-init-main` | 立项主会话：方向未定，先讨论清楚 | 人手动开 |
| `project-init-research.md` | `project-init-research` | 立项副会话：只读调研、带结论回来 | 人手动开 |
| `handoff-main.md` | `handoff-main` | 交接主会话：接手既有项目，先定位再动手 | 换届 / 接手 |
| `system-main.md` | `system-main` | 体系主会话：维护体系资产（总览、模板、提案、知识库） | 体系换届 |
| `qa-proposal.md` | `qa-proposal` | 副会话：答疑 ＋ 提案维护 | 人手动开 |
| `domain.md` | `domain` | 域会话：一域一窗口，＝该域负责人 | 主会话派发后由插件 / 人投递 |
| `subagent-parent.md` | `subagent-parent` | 派子代理的父会话：派之前四项问清（自查卡） | 主会话 / 域会话派子代理前 |

**不放进这个目录的两件事**（口径，别自行加）：

- **最轻档不需要角色文件**：只办一件小事＝完全不上项目体系，也就不开会话。
- **域划分与任务书措辞属 agent 的判断**，不进模板——模板只给结构，不给"你该分几个域"。

## 4. 一个最小例子

以 `project-main.md` 为骨架（下面**删减了正文**，只保留头块与三段标题的形状）：

```markdown
ROLE: project-main
SCHEMA: 1
SLOTS: 项目名, 体系根
---

## 角色

「{项目名}」这个项目的**主会话**：一个项目的统筹者。读项目真值 → 列方案与决策点 → 交用户拍板 → 拆任务派发到域会话 → 合并分支 → 更新 `PROJECT.md` / `KNOWLEDGE.md` 总纲。
**不管什么**：不直接改代码、不执行开发任务、不替用户做判断（只给方案与推荐）。

## 开场

你现在是「{项目名}」这个项目的**主会话**，只统筹、不亲自动手。开工先做三件事，别急着给结论：

1. 读 `{体系根}\{项目名}\PROJECT.md` 的【当前状态】【下一步】——只读与本轮相关的段，**不整读**；
2. 读该项目 `KNOWLEDGE.md` 总纲里与本轮相关的段（已拆域的项目只读 `KNOWLEDGE\{域}.md`）；
3. 要派发之前先刷新体系索引：`node {体系根}\tools\session-registry.mjs`，再只读索引的摘要块 ＋ 本项目段。

然后向我**列方案 ＋ 决策点**（每项给推荐并说明取舍），等我明确说"开干"再动手。

## 规则

- **不直接改代码、不执行开发任务**：所有开发任务一律按派发模板输出「三段式成品」。
- 小改动攒批（3~5 个相关小改动一次派发）；同域要并行 → 在**该域会话内**派子代理。
- `PROJECT.md` 与 `KNOWLEDGE.md` **总纲**只有你能写：落笔前先重读该文件。
- 保持短会话：一个使命做完就收尾，体量大了先压缩再谈换人（不设硬阈值）。
```

要点：

- 头块**逐字**是 `ROLE:` / `SCHEMA:` / `SLOTS:`，到**单独一行** `---` 为止；
- 三段标题**只有这三个**，顺序固定；
- 槽位只写 `SLOTS` 里声明过的名字（上例就是 `{项目名}` 与 `{体系根}`）。

## 5. 维护规则

- **改一个角色的口径：先改 `roles/`**，再回看 `templates/会话开场提示词.md` 的对应段是否要同步（它现在是兜底粘贴版）。**别反过来**——反了就会出现"两处各说一套"。
- **新增角色**：文件名＝`<role-id>.md`，并回 `roles/README.md` 的角色清单表加一行（表是人的索引，不加等于不存在）。
- **不写本机硬编码**：一律写 `{体系根}`（换机只替换一个前缀）。
  **唯一例外**：知识库在宿主家庭目录侧（写作 `~/.dsh/knowledge`），**按固定路径写、不做槽位化**，别改写成 `{体系根}/../...`。
- **通用层 vs 项目特定层（别混读）**：

| 层 | 在哪 | 放什么 | 必需吗 |
|---|---|---|---|
| **体系通用层** | `{体系根}/templates/roles/` | 角色与流程，任何项目都能用 | 是 |
| **项目特定层** | 项目根 `ROLES.md`（模板 `{体系根}/templates/ROLES.md.template`） | 某个项目自己的人员 / 口令 / 特殊约定 | **否**——不存在时流程照样完整可用 |

  ⇒ 所以通用层每个文件的顶部**都不写项目特定内容**；要写项目特定约定，写进那个项目的 `ROLES.md`。

- **现状（如实）**：`roles/` 已按契约落地，但**还有三处指针没回写**——提示词文件的降级说明、体系总览里对应的边界段、派发模板对 `roles/` 的指针，都安排在角色任务书定稿后一次改完。
