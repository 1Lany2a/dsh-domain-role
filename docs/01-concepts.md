# 概念模型

> 这一页只讲**概念**：域 / 会话 / 负责人 / 在任声明、拓扑、生命周期、两条不变量。
> **不讲怎么落地**（消息怎么投、状态存哪、插件有哪些工具）——那在 `02-mechanisms.md` 与 `03-plugin.md`。
> 用词以 `{体系根}/templates/术语表.md` 为唯一源，本文与它保持一致。路径占位符见 `paths.md`。

## 1. 四个词

一句总纲：**把「会话」当成人来管——有身份、有岗位、有在任与离任；消息是请求，不是命令。**

| 词 | 是什么 | 不是什么 |
|---|---|---|
| **域** | 一块**长期职责**的短名（`gui` / `backend` / `docs`），**跨窗口存续** | 不是工作区、不是目录、不是会话本身 |
| **域会话** | 承载某个域的那个**执行会话**（一个顶层 dsh 会话） | 不是身份（载体可以换、可以关） |
| **负责人** | 当前代表该域的那个会话，**是身份、不是载体** | 不是"窗口开着就算"——需要显式声明 |
| **在任声明** | 一行显式记录：「这个域现在归谁」 | 不是任务清单；不存历史、不存任务、不存状态 |

四个词怎么咬合：

- **域**是身份（"这块业务归谁"），**域会话**是载体；**负责人**＝当前的载体在承担这个身份。
- 身份与"哪个窗口"之间**没有可推导关系**：同一个域换一个窗口，域还是那个域。
- 所以"现在谁是负责人"只能**显式声明**（在任声明），不许靠猜。实测理由：使命库 79/95 条没有域标注、近 24h 有活动的 15 个会话里只有 3 个推得出域，靠活动记录会得出"一个域两个活会话"这种自相矛盾的结论。

**四组必须分开说的近似词**（定义见术语表第五节）：

| 别混 | 各自指什么 |
|---|---|
| **域** / **域会话** / **域文档** | 域＝身份（跨窗口存续）；域会话＝当前承担它的那个会话；域文档＝该域的知识文件 |
| **会话** / **窗口** / **工作区** / **worktree** | 会话＝dsh 的运行实体（**含子代理**）；窗口＝用户手开的那个；工作区＝dsh 的 cwd 分组；worktree＝git 检出 |
| **使命** / **任务卡** / **待办** | 使命＝登记单位；任务卡＝派给某个域会话的一段指令文本；待办＝待办区 |
| **子代理** / **官方成员** | 子代理＝父会话派出的 dsh subagent；官方成员＝官方 agent team 名册里的 teammate |

**在任声明 ≠ 域名册**（这两件事常被写混）：

- **域名册**＝"有哪些域"的**派生快照**，从使命库 + 索引派生，不新建存储。
- **在任声明**＝"当前谁在任"这件**不可派生**的事，唯一落盘处是一份极小的声明册：体系侧写 `{体系根}/_registry/domains.json`，插件端由 `domainsFile` 指向它（默认 `<home>/domains.json`，`~/.dsh` 侧）。key 形如 `{项目名}:{域}`，**只存"当前在任"**。

## 2. 为什么身份不能挂在会话上

理由只有一条，但它是整套设计的地基：**会话会关、会换届、会离线，而"这块业务归谁"必须一直在。**

把身份挂在会话上的直接后果：

- **换个窗口 = 换个人**：上一轮的承诺、未决事项、对外口径没有承接对象，交接无从谈起、追责无从谈起。
- **换届没有对象**：想换一个窗口继续做同一块业务时，没有"同一个东西"被交接过去。
- **暂停/终结没有对象**：政策轴（活动 / 已暂停）与生命周期（在用 / 已终结）都得挂在**跨窗口存续的东西**上，才谈得上"按下这个域"。

反过来，把身份挂在域上有两个直接推论：

1. **载体可以换，身份不换**：窗口关了，**域还在**，只是暂时不可达。
2. **换届 = 认领，不是重建**：新负责人面对的是**已经存在**的一批域会话与在任声明，要做的是接手，而不是从零起一套。

**这也是不引入现成 agent team 的真实判据**（2026-10-18 更正后）：

- 官方团队的成员**不是子代理**，而是各自独立的会话 / Agent（各有 inbox、可冷恢复、可互发消息，只有 Lead 能创建 / 指派 / 打断）——所以"成员是子代理"这个旧理由**是错的**。
- 真正的根因是两条：① **roster 与任务板的真值进 Lead 的会话日志、`TeamId = Lead 的 SessionId`** ⇒ Lead 一换届就等于换了一个 Team；② **单进程单工作区**（成员共享 cwd，无 worktree、无跨项目）。
- ⇒ 结论：官方团队给不了"域身份跨窗口存续"。本框架的红线是 **域会话必须是顶层会话、不能是子代理**——判据是「**顶层 vs 子代理**」，**不是"谁开的"**（主会话开出来的顶层会话也可以）。

## 3. 两层同构

| 层 | **身份**（跨窗口存续） | **载体**（可换、可多、会关） |
|---|---|---|
| **项目层** | **项目** | **主会话** |
| **域层** | **域** | **域会话**（＝该域的**负责人**） |

写法上记成一句：`项目 : 主会话 ＝ 域 : 域会话`。

"同构"不是说两层长得像，而是说**两层都有换届、交接、在线 / 离线 / 终结**，于是有三个推论：

1. **主会话也会换届**：新主会话面对一批已存在的域会话，要做的是**认领**（依据＝域名册快照），不是重建。
2. **交接要两个粒度**：**项目级**与**域级**。
3. **载体可以换、身份不换**：窗口关了，域还在。

两层之上还有**人**，人的权限是最高的一条（见 `04-design-decisions.md` 与 `02-mechanisms.md`）：

- 人可直接开 / 关任何窗口，**不经主会话**；
- 人**可否决**主会话的立域 / 交接决定；
- 人可直接对任意域会话下指令，**优先级高于主会话**。

## 4. 拓扑：星形（以及它的单点）

**跨域消息一律经主会话**，不直连：

```text
域 A ──▶ 主会话 ──▶ 域 B
```

选星形、而不是网状，有三个理由（按权重）：

1. **协议最精简**：一种地址、一条路由。网状还要另定直连权限、冲突仲裁、可见性规则。
2. **状态集中**："谁在线、谁是哪个域"只在主会话一处维护，好推理、好调试。
3. **域是长期稳定的划分，跨域通信本应低频**。若两个域频繁通信，**更可能是域边界画错了**，该拆该合。

- **两层星**：每个项目一个中心；跨项目通信 ＝ 项目主会话 ↔ 项目主会话，**仍然是星形**。
- **唯一硬伤 ＝ 单点**：主会话换届 / 崩溃 / 关窗 ⇒ 跨域通信全断。
- **兜底**：换届交接包**必须包含**「**在途跨域通信**」＋「**域名册快照**」。交接（＝负责人变更）还需要**公告**，内容含：未决事项、对外承诺、**在途消息**，并同步更新在线映射。
- **明确不做的事**：不建网状直连（暂缓，等有真实跨域消息样本再定）；不把子代理当作域的代表。

## 5. 生命周期：在线 / 离线 / 终结

**状态模型是"两个轴 ＋ 一个生命周期"**，不是一个大枚举：

| 轴 | 谁给 | 取值 | 存在哪 |
|---|---|---|---|
| **事实轴** | 宿主给，**只读** | **在线 / 离线** ＝ 有没有活 Agent | 不落盘，每次现算 |
| **政策轴** | **人给，可逆** | **活动 / 已暂停** ＝ 字段 `paused` | 运行期状态目录 |
| **生命周期** | 插件的 `release_domain` | **在用 / 已终结** | 同一条状态记录里的 `terminatedAt` 墓碑 |

对外只给**五种派生状态**（派生、**永不落盘**）：

| 派生状态 | 含义 |
|---|---|
| **在线 · 活动** | 有活 Agent，也没被按下（正常） |
| **在线 · 已暂停** | 有活 Agent，但**某一级**被按下（暂停不改在任身份） |
| **离线 · 活动** | 没有活 Agent，政策上活动（窗口没开 / 重启后没加载） |
| **离线 · 已暂停** | 没有活 Agent，而且被按下 |
| **已终结** | 已经 `release_domain` 退役（墓碑；域名册里那条声明已被删） |

**"在线"必须读准**（这是最容易写歪的一条）：

> **「在线」＝权力与责任的在线，不是"能不能说话"。**

- 退役 / 离线的会话**仍可被人打开对话、也仍能主动发消息**（实测：已退役的会话照样能收发）。
- 所谓"在线"只表示：**它有活 Agent、能承担在岗责任、可作默认投递目标**。
- ⇒ 判"这个域有没有人管"看的是**在任声明 ＋ 在线**，不是"窗口还能不能收发消息"；反过来，**离线 / 已终结 ≠ 失联**，只是**不该再往那儿派活**。
- ⇒ 另一条同源的坑：**存在 ≠ 在线**。重启后会话只是"在列表里 / 在存档里"，旧会话往往要被人点一下或被 resume 才会活；判在线只能看进程里有没有活的 Agent。

三态速查：

| 状态 | 还能投递吗 | 处置 |
|---|---|---|
| **在线** | 能（被暂停时另说，见 `02-mechanisms.md`） | 正常派活 |
| **离线** | 默认**不排队**，明确报"**不可达**"；要送必须显式 `wake` 且**接线可解**，否则**拒绝拉活** | 派活走 `create_domain_session`（宿主建的新会话装配完整）或让人在 GUI 点开它；也可以在任声明上换人（交接） |
| **终结** | 不接收（`release` 已写墓碑） | 不再派活；该域以后不做了 |

## 6. 两条不变量

**不变量一：一个域只有一个负责人。**

- 同域多在线是一**违规状态，不是容错**：发现就**报警**，**不"挑一个投"**。
- 理由：两个"负责人"同时写同一批文档，冲突不是概率问题而是时间问题；自动挑一个会让事故不可追。
- ⇒ **并发 ≠ 多负责人**：要并行就在**该域会话内派子代理**（子代理是负责人派的临时工，**不代表域**）。

**不变量二：域的负责人必须是顶层会话。**

- 子代理随父会话结束就消失，顶不了这个位置：它**对外发言、写域文档、做承诺**都不算数，仍由负责人署名。
- 判据是「**顶层 vs 子代理**」，**不是"谁开的"**（主会话开出来的顶层会话也可以当负责人）。

**配套（不是不变量，是前置条件）**：**在任需要显式声明，不许靠猜**——"某域是否在线"这件事问的不是"某个窗口开着吗"，而是"**哪个会话当前被授权为该域负责人、且在线**"。

## 7. 对照表：域 / 会话

| 问题 | **域** | **会话（域会话）** |
|---|---|---|
| 是什么 | 身份：一块长期职责，跨窗口存续 | 载体：一个运行中的 dsh 顶层会话 |
| 会不会换届 | **不换**——换届换的是代表它的会话 | **会**：换届、交接、关窗、重启 |
| 谁持有它 | **负责人**（由在任声明记录） | 会话自己（dsh 的运行实体） |
| 怎么寻址 | 按**域**寻址，再由机制解析"当前负责人是谁" | 按**会话 id** 直接寻址 |
| 关掉 / 失败会怎样 | **域还在**，只是暂时不可达；换一个会话继续代表它即可 | 变**离线**（不是终结）；要恢复得靠人点开或 resume（且"叫醒"≠"能干活"） |
| 退役怎么表示 | `release_domain` 写墓碑 ⇒ **已终结** | 会话级**没有**对应"终结"档位；停用一个会话实际用 `set_domain_state(scope='session')` 暂停来近似 |
| 能否并行 | 一个域**只能有一个负责人**；并行下沉到子代理 | 同一时刻可以是多个独立会话（但**不能都代表同一个域**） |
