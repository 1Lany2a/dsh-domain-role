# 机制

> 这一页讲「为了让上面那套概念真的跑起来，都装了什么机关」，每条都写**它防的是什么问题**。
> 概念见 `01-concepts.md`，插件侧实现见 `03-plugin.md`，为什么这么选见 `04-design-decisions.md`。

## 1. 在任声明：把「谁负责」写成一行字

**怎么做**：一份极小的声明册，一条一行：`{ 项目:域 → 会话 id, since, by, note }`。写入是**原子替换**（写临时文件再 rename），读不懂就中止不写。

**防的问题**：靠猜「谁负责哪个域」。实测过：使命库 79/95 条没有域标注，近 24 小时有活动的 15 个会话里只有 3 个推得出域，还出现过"同一个域两个活会话"这种自相矛盾的结果。猜不出来，就必须显式存。

**边界**：只存**当前在任**，不存历史、不存任务、不存状态。历史在会话存档与 changelog 里，任务在使命库里。

## 2. 四级暂停：任一级按下即停

**怎么做**：四个作用域——`domain`（域）／`session`（主＝单会话）／`project`（项目）／`global`（全局，保留键 `*`）。判定是 **OR 叠加**：任一级被按下就拦。**两端都查**：接收端（目标域／会话／项目／全局）＋ 发送端（本会话／本会话项目／全局）。

**防的问题**：只按域暂停会留缝——上级按下了，下级照样发得出去。反过来，「域级暂停只关那扇门」，不禁言会话本身（它还能收发别的消息）。

**细节**：

- `global` 的按／解都要显式确认，缺了**一个文件都不写**。
- 恢复＝**逐条重评 OR**：只重投"现在不再被任何一级压着"的消息；仍被别的级压着的保持入队，并如实报出"还被谁压着"。
- **暂停不改在任身份**：声明册里那条记录不动。
- **暂停不拦人工唤起**：人自己点开、宿主自己 resume，插件拦不住，那正是"人工手动唤起"。

## 3. 投递与队列

**怎么做**：一条域间消息按固定顺序走——**解析目标**（声明优先，索引标注兜底）→ **判在线**（有活 Agent 才算）→ **过暂停闸** → **投递或落盘入队** → 必要时叫醒。

**防的问题**：静默的"看起来成功"。具体三条：

- **离线不排队**：目标窗口没开，就明确报"不可达"，不制造"已送达"的假象。
- **被暂停不硬投**：消息落进持久队列（一行一条 JSONL，重启不丢），回执写清"被谁、在什么时候按下"，并给可撤回的队列 id。
- **不许静默换人**：目标不可达时不会自动挑另一个会话顶上——那会让事故不可追。

**叫醒（wake）**：只解决"在线"，不解决"能干活"。拉活需要"接线"（模型 ＋ 预设）；取不到接线就**不拉**，宁可如实报不可达，也不拉起一个跑一轮就崩的会话。

## 4. 交接：负责人变更，不是"再开一个"

**怎么做**：换届／交接＝**负责人变更**，需要**公告**；交接包给出接手方要的开局材料。

- 交接包默认产物是 **JSON**（机器读、待办存全文不截断）；要给人读时同一命令加 `--handoff-md` 现渲一页 MD。
- **行数与条数的限制只属于渲染层**，不许反过来裁剪真值。
- 交接内容必须含：未决事项、对外承诺、**在途消息**、以及**域名册快照**。

**防的问题**：换届时"上一轮的承诺没人接"。星形拓扑的唯一硬伤就是主会话单点——主会话换届或崩溃，跨域通信全断，所以兜底只能写进交接包。

## 5. 编号

**怎么做**：使命名带域：`S##-<域>-<slug>`；分支 `feature/<使命名>`；commit 带编号；达成报告文件名带编号。编号**跨使命不重用**，从当前最大编号 +1。

**防的问题**：贴错标签、混来源、事后追不到"这件事当时谁做的"。顺着编号能同时查到会话标题、分支、commit 与达成报告。

**历史条约**：历史的短号（`S##-<slug>`，没有域段）**不迁移、不回填**——它们已经埋进分支名、commit 与报告文件名里。跨项目的唯一键统一用**全使命名**。

## 6. 唯一写者

**怎么做**：分层定死写权限。

| 文件 | 只能由 |
|---|---|
| 项目 `PROJECT.md`、`KNOWLEDGE.md` **总纲** | 该项目主会话 |
| `KNOWLEDGE/<域>.md` | 该域负责人（落笔前先重读该文件） |
| 体系文档（`SYSTEM-OVERVIEW.md`、模板、提案） | 体系主会话 |

**防的问题**：两个人同时改同一份真值 → 后写的覆盖先写的，而且没人知道覆盖发生了。配合"改共享文件前先反查最近谁碰过"（`session-registry.mjs --file <路径>`）把冲突从"事后发现"变成"事前避开"。

## 7. 审计闸

**怎么做**：git 提交前过一道钩子——**改了代码就必须有对应的审计日志**（落在项目 `projectlog/`，同一次操作共用一个 TraceID），没写就过不去。

**防的问题**：靠记性写日志。规则机械化之后，"忘了写"变成"提交不了"。

**格式要求**：入口（要干什么、关键输入）／关键分支（判断结果）／结果与异常——异常必须记，那是排障的命根子。

## 8. 提案机制

**怎么做**：想法先分流——急着落地进待办；值得讨论但还没定的，写成一份提案（背景／方案／复用／实现／风险·待决策点／优先级／前提与反面证据）。

**防的问题**：待办区被"候选"淹没；以及 AI 拿一个未经验证的前提一路完善下去（"完善的垃圾"）。所以提案模板里有一节**证伪闸门**：把方案成立依赖的前提挖出来，逐条问"若为假会出现什么可观察失败／知识库有无反面证据／能否最小成本先验证"。

## 9. 防熵体检

**怎么做**：按四个指标量体温——巨型单文件、文件疯涨、僵尸堆积、分支堆积。**只统计自家代码**，排除 vendored 与文档。

**防的问题**：项目在"还能跑"的假象里烂掉。策略是**只量体温、不治病**：红灯只触发一次评估（要不要拆／归档／合并），不做自动清理。

## 10. 一张对照表

| 机制 | 防的问题 | 失败时的样子（被防住的） |
|---|---|---|
| 在任声明 | 「谁负责」靠猜 | 同一个域两个"负责人"各写各的 |
| 四级暂停 | 上级按下了、下级照发 | 暂停期间还有活被递进去 |
| 投递与队列 | 静默成功／静默换人 | 以为派了活，其实没人收 |
| 交接 | 换届断线 | 承诺与在途消息丢了 |
| 编号 | 贴错标签、追不到 | 事故复盘找不到原始报告 |
| 唯一写者 | 并发覆盖真值 | 两份口径互相覆盖 |
| 审计闸 | 忘了写日志 | 修完 bug 说不清改了什么 |
| 提案机制 | 待办被候选淹没／前提未验 | 精致的垃圾 |
| 防熵体检 | 在"还能跑"里烂掉 | 单文件几千行、分支堆着不删 |
