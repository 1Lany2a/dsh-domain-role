# 派发任务模板（主会话专用，按需读取）

> 用途：主会话派发任务时读本文件，按格式直接输出。
> 只在需要派发任务时读取，不内嵌进开场声明——省 token。

## 主会话铁律（最高优先级，先读这条）

**主会话只统筹、派发、合并，绝不直接改代码或执行任务。**
- 所有开发任务（哪怕改一个常量）都必须走三段式派发给该域的窗口
- 主会话唯一例外：只写 PROJECT.md / KNOWLEDGE.md（唯一写者），
  且提交前 touch .main-writer-flag
- 若任务小到"不值得开会"，攒一批相关小改动合并成一次派发，
  而不是主会话自己动手

## 派发准则（拆任务前先读，省冷启动成本）

1. **强相关小任务合并**：多个小改动若都碰同一模块/同一文件，
   合并进**同一域会话**（一个使命、多步小提交），不要各开一个——
   每次新开窗口都有冷启动成本（读文档全价，无缓存）；**域会话下这条已由"窗口长期活着"天然满足**
2. **独立大任务才拆分**：改动面互不重叠、可并行验证的大任务才拆到
   **不同域会话**并行；**同域要并行 → 在该域会话内派子代理**（2026-10-09 裁定）
3. **小改动攒批**：改常量/改文案/单文件小修，不单独开会——
   攒够 3~5 个相关小改动，一次派给该域会话
4. **判断标准**：犹豫"这个任务够不够大"时，倾向合并
5. **底线**：无论任务多小，主会话都不自己改代码，一律派发
6. **体系侧待办排序规则（2026-10-13 定，A3「甲」；同日晚按代码实测校正）**：体系侧待办**唯一源＝`PROJECT.md` §下一步**（`SYSTEM-OVERVIEW.md` §五 只有指针）。该节**按优先级排序、最要紧的放最前**——一页纸（`--handoff-md` 的 §三；⚠️ `--handoff` 默认只出 JSON、没有 §三）取 **体系根最多 6 条** ＋ **各项目各 3 条**（最多 6 个项目）、**整页 62 行**上限；**缩进子项也占名额**；**`[x]` 开头的条目会被跳过**；**取法是"取头"**（代码只在"整节纯编号且编号递增"时才改成取尾＝最新；本节混有子项 ⇒ 取头）。⇒ **露出的就是列表最前的 6 条**＝"按优先级排的就是会被人看到的"；**完成项要么标 `[x]`、要么迁 `SYSTEM-changelog.md`**，别占名额。调优先级＝在 `PROJECT.md` 里**重排本列表**，**不许另写第二份待办**（那就是 2026-10-11 否掉的那条路）。

## 提案机制（想法→提案分流，2026-09-02 定）

**对话中用户提到想法 → 主会话判断**：

1. **急着落地 / 直接可做** → 进 PROJECT.md 待办区，正常派发执行
2. **不急着落地 / 值得讨论**（需要调研、方案未定、可能不做）→
   **问用户"要不要做成提案"** → 用户确认 → 生成
   `提案\提案<YYYY-MM-DD>-<主题>.md`（用 `templates\提案-template.md` 格式）
   - 日期格式：`2026-09-02`；主题：简短中文，如 `RAG知识库问答`
   - 命名示例：`提案\提案2026-09-02-RAG知识库问答.md`
   - 旧命名 `提案N-主题`（如 项目甲 提案1~4）保留不迁移，新规则从下一份提案生效

3. **PROJECT.md 待办区记一行**：`提案 <日期>-<主题> 待决策`
   （主会话唯一写者顺手维护，决策后更新状态）
4. **提案讨论**：提案本身不占窗口——值得深挖时**单开副会话讨论**，
   产出结论后由主会话更新提案状态（决策实施 / 放弃）

> 提案格式：`templates\提案-template.md`（6 章节：背景 / 方案 / 现有资源复用 / 实现思路 / 风险·待决策点 / 优先级建议）


## 域会话（2026-10-01 起为默认形态）

**默认形态：一个窗口长期负责一个域**，里面一件件放使命——不再是"一任务一窗口"。

- **域**＝一个方面（如 GUI / 后端 / 构建 / 数据）。**任务属于哪个域，就放进那个域的窗口。**
- **新域才开新窗口**；没同域会话时才新开。
- **术语口径（2026-10-09 统一，唯一源 `templates\术语表.md`）**：**域会话 ≠ 窗口 ≠ 工作区**；布局名用「**一域一窗口**」/「一任务一窗口」；**负责人**＝当前代表该域的那个域会话，**一个域只有一个**（同域多在线＝**违规状态**、不是容错；要并行就在该域内派子代理）；**子代理**＝dsh subagent（⛔ 别叫"子会话 / 子智能体"）；状态用**在线 / 离线 / 终结**（"死亡"仅口语）。
- **一个域会话可以横跨多个工作区**（实测：gui 域会话在 `项目乙` / `-s20` / `-s22` 三个 worktree 里干过活 ⇒ **域文档副本可能不止一份，同步责任在该域会话**）。
- **域名单（白名单，必须与索引脚本同步）**：`gui` `backend` `frontend` `build` `data` `test` `docs` `infra` `cli` `api` `ui` `db` `perf` `security` `config` `deploy` `asr` `vision` `pipeline`。**新域要两处一起加**：本节 + `tools\session-registry.mjs` 的 `KNOWN_DOMAINS`（索引靠它把域统计出来，漏加则该域显示为"未标域"）。
- 窗口的**寿命与换人（2026-10-08 改口径：取消硬阈值）**：窗口体量 **>500k**、或域记录 **>14 天** ⇒ 索引只打 ⚠ **软信号**，它不是换人开关。**先压缩**（手动/自动都算），压缩后仍很大且该域还有多件活，再由用户/主会话临场决定是否交接（旧窗口写"这个域试过但没走通的路"，见域文档模板）。**别再写 150k 硬线**——实测那等价于"一域一使命"，直接退回旧的子会话机制。
- **主会话多一项职责：分发**——每件活完成后判"这条结论影响哪个别的域"，写进总纲或直接告知对应窗口。
- **验收不放松**：域会话是新窗口也好、老窗口也好，产出照样要落盘 + git 分支 + 达成报告；**别因为"是同一个窗口"就少查**。
- 学习域（`study\`）与零散小项目**不强制分域**——没拆域就照旧一任务一窗口，**两种形态并存**。

**在任声明（认领）**（2026-10-10 新增）：接手某域前，先把"当前在任"显式写进**在任声明**（`{体系根}\_registry\domains.json`）——框架 §五「在任需要显式声明，不许靠猜」；实测靠使命库、窗口活动都推不出"现在谁是负责人"。
- 命令：`node {体系根}\tools\domain-owner.mjs claim <域> --session <会话id> --project <项目名>`（幂等；该域已被别的会话占用则默认拒绝、退 3，换人加 `--force`＝交接）。
- **诚实说明**：目前**只能由主会话 / 人代认领**；域会话自己认领要等插件工具，属第二步、需重启 dsh 才生效。
- 边界：**在任声明**只存"当前在任"，一行一个域，key＝`<项目>:<域>`，**不存历史、不存任务**。

**重启后动域会话 · 检查单（2026-10-13 加，F3；机制口径同 `SYSTEM-OVERVIEW.md` §三 三级会话协作节）**：
1. **存在 ≠ 在线** —— 重启后会话只是"在列表里 / 在存档里"，**要有活 Agent 才算在线**；旧会话往往要**被人点一下或被 resume 才会活**。判在线只能看进程里有没有活的 Agent，**别看那个列表**。
2. **重启后先等几分钟再决定换届** —— GUI 会在这几分钟里陆续把窗口拉起来，早判＝误判。
3. **接管/换届前先确认或叫醒前任** —— 插件已支持**静默叫醒**（`ctx.agents.resume`：把会话拉活、**不跑回合、不派活**）；先叫醒再交接，「（已退役）」这类标记才落得上。⚠️ **但"叫醒" ≠ "能干活"**：2026-10-13 真机，`resume` 拉活的会话**跑回合会在 100 ms 内崩**（`prompt variable "{{model}}" has no value for this assembly (section "deployment:persona-prefix")`）、**零产出**；而 GUI 自己拉起的会话同一时段正常。⇒ **给离线会话派活要走 `create_domain_session`（宿主建的新会话装配完整）或让人在 GUI 点开它**；**`wake='probe'` 永远发现不了这个坑**（probe 不跑回合）。
4. **在任 ≠ 可达** —— 声明册里写着你在任，**不等于消息送得到**（目标可能离线；离线不排队）。
> ⚠️ **硬事实（2026-10-12 查实）**：**静默投递（`inject`）不是耐久队列** —— **未读的入队消息在 dsh 退出/重启时会被整体取消**（实测 2026-10-12 23:45:48，三个不同会话的待读注入**在同一秒全部 `canceled`**）⇒ **跨会话派活只有两条路**：用 `followup`（真唤醒、有成本），或**先把任务落盘、重启后再重投**。

## 优先复用原会话（2026-09-01 定；2026-09-16 用实测数据修正成本口径；**2026-09-20 定判据；2026-10-01 并入域会话形态**）

**相关性强、可利用原会话上下文的任务，优先派给原会话。**
**核心原则（2026-09-20 重定）：该不该复用，看"同域 + 窗口还活着 + 没失控"——不看它多大、也不看它多"热"。**（2026-09-16 修正的"不看它多大"仍然成立：体量影响**质量**，不影响成本；完整判据见下方「派发新任务前」三条判据。）

- 旧口径**两头都过头**，2026-10-08 修正：缓存读单价是输入的 **1/10**（DeepSeek 系 $0.028 vs $0.28 每 M），重发历史便宜**但不免费**——每一步都要按这个价重读**整个**上下文。单步花费 ＝ `新增输入×0.28 + 缓存读×0.028 + 输出×0.42`（每 M token），看**哪一项大**：每步新增内容多时新增项主导；**长窗口且每步新增小时，缓存读是大头**（2026-10-08 三窗口 801 步：cacheRead 占 token **97.3%**、占成本 **62~82%**；同窗口单步成本随上下文涨 **5.4~7 倍**：105k \$0.0033 → 508k \$0.0225）。
- **要盯的两件事**：①**每轮新产生的内容**（大工具输出、整读大文件、巨型 diff）——实测有会话峰值仅 19k 却花 \$2.06（168 步），另一个 402k 花 \$3.95（174 步）②**长窗口里上下文的"地板价"**——**压缩立省 77%**（asr 窗口 656k \$0.0258/步 → 压缩后 250k \$0.0059/步），比换窗口划算且不丢域上下文。
- 真正该盯的红线是**单步异常贵**（实测最贵单步 $0.41 ≈ 均值的 18 倍）→ 说明某一轮塞了巨大内容，该去查那一轮干了什么。
- 上下文长度仍有**质量意义**（越长越易被污染、注意力稀释、压缩丢信息），但那是**准确性**问题，不是成本问题。

**第 0 步（2026-09-16 加；2026-09-18 改为指向共享索引）：先刷新并读体系索引 `{体系根}\_registry\INDEX.md`**

- **触发点二（改共享文件前）**：`node {体系根}\tools\session-registry.mjs --file "<路径>"` 反查"这文件最近谁碰过、有没有跨 cwd / 近同时"。共享文件＝`{知识库}\*`、`SYSTEM-OVERVIEW.md`、`templates\*`、`提案\*`、`_registry\*`、`tools\*`。
- **索引放共享目录**（`{体系根}\_registry\`，不在任何 git 仓库内）→ 所有会话、所有 worktree（含 zcode）都读得到；**不在项目内放副本**（实测主工作区未提交的文件在 zcode worktree 里根本不存在）。
- **里面没有一列是手抄的**：全部由脚本从使命库（`feature`/`status`）+ git 分支 + 会话存档生成。原来那张手维护的"子会话登记表"已退役（见"会话编号规则"节第 3 条）。
- **编号是索引主键**——同一个编号同时出现在会话标题（`【使命】S##`）、分支（`feature/S##-*`）、commit（`feat(S##):`）、达成报告（`.dsh\missions\S##-*.md`）四处，顺着它可从索引查到报告与当时的过程（review / bug 追责用）。
- ⚠️ **硬约束（别承诺做不到的事）**：① `send_message` 仍只允许"父 ↔ 直系子代理"互发（源码 `dsh-subagent\lib\index.js` `sendMessage`，非直系报 `is not a direct child`），**对独立会话不管用**；② **但"够得着顶层会话"这面墙已于 2026-10-10 ~ 10-11 拆掉**：插件 `dsh-domain-bridge` **v0.2.0** 的 `send_to_domain(target=<域 或 会话 id>, mode=followup|steer|inject, dryRun)` 能往**在线**顶层会话追加一条普通消息并唤醒它（`dryRun=true` 免费，先探再用）；按域寻址优先走**在任声明**（`_registry\domains.json`），声明里的负责人离线时**不投**、报 `declared-owner-offline`。**仍做不到的**：目标窗口不在线就**不排队**（"窗口开着就通"）；**不能程序化把窗口拉到前台**——2026-10-11 A′ 探针结论是"部分可达"（宿主侧能调 `sessionController.create()` 开出新会话、并自动出现在侧边栏，但全链路没有 Host→Renderer 导航通道，最后一下仍得人点）。所以"复用"的实操＝**在任负责人在线就投**，否则回到老两条：**让用户回到那个窗口**，或**读它的达成报告**。
- 只有主会话**自己在本次会话里派过的子代理**（`list_agents` 可见，status `idle`/`ready`；**关掉了也能 cold-resume**）才是真能接着说话的。
- **顶层会话不在此列**：它走 `send_to_domain`（见上一条硬约束），不走 `send_message`。
- **异常不阻塞**：索引跑不出来 / 无 node / 表为空 → 跳过本步按老流程走，**索引是加分项不是门禁**。

派发新任务前，按下面**三条判据**依次判断（**只有第 1 条是一票否决**；2026-09-20 重定，替代原"相关性 + 状态 + 还剩多少活"四情形）：

1. **同域吗（唯一的一票否决）**：同模块 / 同文件族 / **同一段代码或同一个设计决策**（如都改 GUI、都碰 CollectorGuiApp.cs、都在同一套配置读写路径上）→ 强相关；无交集 → 弱相关 → **新开**，后面都不用看。
2. **窗口还活着吗（硬门槛）**：看索引的**「窗口」列**。
   - 主会话**无法**用 `send_message` 接管人工开的窗口，但**能用 `send_to_domain` 往它投任务卡**（窗口必须在线）→ 窗口活着，"复用"才可能（老办法＝让用户回那个窗口贴任务卡）。
   - 拿不准 → **不用问用户**，在任务卡里写条件句："S## 窗口若还开着就贴到那里；否则按新会话执行"。
3. **热不热（加权）**：看**「最后活动」列**（＝最后一轮对话结束）。
   - **< ~2 小时**（缓存还热）→ 复用几乎零额外成本 → 明显偏复用。
   - **跨天** → 复用要多花一次性全价重读（约 $0.056@200k），且**窗口对代码的认知可能过时**（期间别的会话可能已合并提交）→ 天平偏新开。但**不足以单独否掉复用**。

**加权项（不是阈值，别写成硬指标）**：

- **体量 × 剩余活量**：体量大 + 只差收尾 → 复用；体量大 + 还有几十步 → 偏新开；**体量大但只有一个使命、内容全相关 → 不算失控**（一个简单任务读几个大文件、跑几十次工具调用，上下文自然就大）。**不设硬阈值**——体量**不是成本红线**（无 100k/150k 悬崖），但**长窗口要主动压缩**（2026-10-08 实测：同窗口单步成本随上下文涨 5.4~7 倍、压缩后 −77%）；体量同时影响**质量**（长上下文易污染/丢信息）。参考：实测一个"7 轮"会话因 380 次工具调用累积到 663k——**轮数少 ≠ 上下文小**，工具调用内容才是大头。
- **`↺N`（复用次数）**：同域反复用同一个窗口＝健康；跨域混装＝噪声多 → 偏新开。

**任务是否完成（决定"怎么复用"，不决定"要不要复用"）**：

- `进行中` → 回原窗口接着干（同一使命，**不重复 declare**）。
- `已完成` → 回原窗口，但 **declare 新使命**（索引里的 `↺N` 就是这么来的）。
- `已完成` 且**没落盘** → 先让它把没写进 `PROJECT.md` 的东西落盘，再决定。

**落盘（保险丝，不是判据）**：它决定"万一步到新开"的代价——落盘完整，新开几乎无损；**没落盘，那个窗口就是唯一副本，关了就永久丢**。

**为什么"已完成"也优先复用（2026-09-20 补）**：

- 修 bug 最省的路是问"**当初为什么这么写的人**"。`PROJECT.md` 变更历史记的是**结果**（根因/改了什么），**不记当初否掉了哪些方案、绕开了什么约束**——而 bug 往往就藏在这些取舍里。
- 同域新任务同理：这个域的坑（编译、编码、验证手法）是**跨任务复用**的。体系历史实证：`sess-06565978 ↺12`、blog `sess-40da7265 ↺4`、项目甲 里 **S14/S15/S17 都由 S07 会话执行、S19 由 S18 会话执行**。
- 真正让复用变差的是**旧上下文里与当前任务无关的内容**（跨域混装），不是"使命已完成"。

**决策表**：

| 同域 | 窗口活着 | 热（<2h） | 体量 × 剩活 | 决策 |
|---|---|---|---|---|
| 否 | — | — | — | 新开 |
| 是 | 否 / 不确定 | — | — | 新开（任务卡附前因线索 + 条件句） |
| 是 | 是 | 是 | 不臃肿 | **回原窗口**（已完成的 declare 新使命） |
| 是 | 是 | 否（跨天） | 不臃肿 | **回原窗口**，但提示"它的认知是 N 天前的" |
| 是 | 是 | — | 臃肿且活还多 | 偏新开（附前因线索） |

**好处（2026-09-20 修正）**：复用的真实收益是**窗口里那些没落盘的隐性知识**（它为什么这么改、哪条路试过不行），**不是省 token**——新会话冷启动读 PROJECT.md + KNOWLEDGE.md 只有 $0.002~0.004 量级，可忽略。附带好处：不必重复建分支、不必重复交底。
6. **上下文卫生（执行窗口的义务，2026-09-01 定；域会话下更重要——窗口寿命长）**：
   - 禁止整读大文件——用 grep 定位 + read 指定行段（已定"精准读指令"）
   - 工具调用精简：read 只取所需行段，不整读；大输出注意截断
   - 一个使命做完（5 段报告写完）→ 建议收尾关闭，不无限挂机（**关掉不影响复用**：存档还在，用户重新打开即可，索引「窗口」列会显示它最近被加载过）
   - 目标：一个使命在该域会话内用 20-50k token 完成；**窗口变大不再是"必须换人"的理由——先压缩**（实测压缩 −77%/步，依据见 `{知识库}\aspects\ai-workflow.md`）。体量 >500k 时索引会打 ⚠，那时优先**压缩**而不是换窗口。

> 例外：并发需要（同域多任务要并行跑）时，**在该域会话内派子代理**（分工不重叠 / 不写他人文档 / 汇报不算证据），**不再多开一个域会话**——**一个域只有一个负责人**（2026-10-09 裁定；口径唯一源 `templates\术语表.md`）。

> **子代理派发规则（2026-10-11 起 · 指针）**：**主会话与域会话都可在自己会话内派子代理**（`subagent` / `subagent_fork` / `workflow`），**子代理无权再派**；派发前**必读**一页纸规则 `templates\子代理派发规则.md`（授权范围 + 三条护栏 + 三条使用口径，出处见提案 §2.1）。**本文件不复述全文。**

## 修错流程（谁的错谁修，优先回原会话）

1. **原窗口还开着** → 直接回到那个窗口（它记得自己为什么这么写），贴出 bug 现象
   让它修。它记得自己为什么这么写，上下文连贯、缓存命中，
   修得快且省 token。修完在原分支补提交（fix: 英文 message）。
   ⚠️ 但若原会话体量已很大、质量已受影响（长上下文易污染/丢信息，见"优先复用原会话"节）→
   重开新会话修更稳妥（附 bug 现象 + 原使命达成报告 + 相关文件 + **当初的约束/取舍**）。
2. **原窗口已关闭** → 才新开修。三段式【使命】命名
   fix-<原使命名>，【任务】里必须附上：bug 现象 + 原使命
   达成报告位置 + 相关文件/函数名——新会话没有上下文，
   不给线索它会瞎猜。
3. **分支**：原分支还在 → 继续用；已合并删除 → 新建
   fix/<原使命名> 分支。
4. **不重复 declare**：同一使命的修复不重新注册使命（避免
   流程膨胀），修复记录写进审计日志 + 达成报告补充说明。
5. **原则**：任何 bug 修复都优先回原会话，新开会话是
   最后手段（原会话已关/跨天无法恢复时）。

## 会话编号规则（每次派发必做，防贴错标签）

1. **按顺序分配编号**：S01、S02、S03…（S = Sub，两位数起步）。
   从项目当前最大编号 +1 开始，跨使命不重用。
   > **zcode / 外部 agent 编号另见协议**：用 `Z<项目字母>##` 项目号段（项目字母由体系主会话在 `templates\zcode-protocol.md` 分配登记），本节只讲 dsh 会话 `S##`。
2. **编号写进使命名和分支名；域会话起，域名进序号后面**（2026-10-01 加）：
   - 使命名：`S03-<域>-fix-export-crash`（域用**英文小写短词**：`gui` / `backend` / `build` / `data`…）
   - 分支名：`feature/S03-<域>-fix-export-crash`
   - commit message 带编号即可：`feat(S03): ...`
   - **域放在编号后**，是为了让 `S##` 前缀在分支/commit/报告里**语义不变**（历史引用不受影响）。
   - **实测**：本机 git 2.55.0 支持中文分支名（`feature/S01-后端-x` 可建可提交）；但域仍建议用英文——与 slug 同规则、跟其它工具链一致，省得下游脚本踩编码。
   - 索引按这个格式**自动抽域名**（`S##-<域>-…` → 域＝第 2 段）；旧使命没有域名，显示为"未标域"，不报错。
3. **不再手维护"子会话登记表"（2026-09-18 退役）**：
   原规则＝"派发时在 `PROJECT.md` 登记一行、complete 后改状态为 done"，那 4 列
   （编号/使命/分支/状态）**全部可从现成来源推出**（使命 JSON 的 `feature`/`status`、git 分支、编号前缀）→
   已由共享索引 `{体系根}\_registry\INDEX.md` 完整覆盖，**不要再抄一遍**。
   - 退役理由：体系里**不存在"人工维护"环节**（登记的同样是 AI 读别处数据再抄一遍），
     所以代价不是"人手"而是 **①AI 每次重抄的 token ②漏维护**——实证：7 个项目里 3 个根本没有这张表，机制已断。
   - 各项目 `PROJECT.md` 里**已有的历史表保留不删、停止更新**（别抹掉历史）。
4. **好处**：GUI 里哪个标签是哪个域的窗口一目了然
   （贴三段式时【域】行自带编号）；出 bug 说"S03 有问题"，
   主会话查索引即知；git 历史全链路可追溯。

> **历史编号不迁移**（2026-10-01 定）：`S##-<slug>`（无域段）的老使命**保持原样**，不改名、不回填——短号已埋进分支名、commit 与达成报告文件名。新格式从**下一件活**起生效。

## 达成报告（必填字段，2026-08-30 定）

> **本节是「达成报告」的唯一源**（2026-10-18 定，用户拍板 L1④）。其余文档（`SYSTEM-OVERVIEW.md`、`mission-template.md`、`project-map-cheatsheet.md`、`zcode-protocol.md`）**只许写指针 + 一句摘要**，字段含义以本节为准；要改格式，先改本节，再回头改那些指针。

窗口（一域一窗口 / 一任务一窗口 都一样）执行 `mission.mjs complete` 写达成报告时，**必须**按以下 5 段输出（顺序固定）：

```
[文件清单]：仅列新增/修改的文件路径（相对项目根，一行一个）
[依赖新增]：如引入第三方库，写清名称+版本号；未新增写"无"
[未处理异常]：明确告知哪里可能崩/什么场景会失败；无则写"无"
[接口签名]：仅当本任务涉及函数/API/数据结构签名变更时填写（函数名+入参+出参）；
            不涉及接口变更的任务必须写"N/A"，不许留空
[自测用例]：至少 1 个已实际执行并通过的手动测试描述（做了什么+预期+结果）
```

判定规则：
- **[文件清单][自测用例][未处理异常][依赖新增] 四字段必填**，缺任一字段 → 达成报告不完整，退回该窗口补齐后再验收
- **[接口签名] 条件必填**：任务涉及接口/签名变更 → 必须填；任务不涉及（改文案/配置/文件移动/文档）→ 写 "N/A" 即可。**不得**把"没填接口签名"当作任务失败——非接口任务没有可填的签名，这是正常情况
- 报告体量：每条一行，控制在 10 行内，不写废话
