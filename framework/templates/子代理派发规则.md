# 子代理派发规则（一页纸 · 照抄即可执行）

> **口径来源**：`提案\提案2026-10-09-会话互通与子代理.md` **§2.1**（授权 + 三条护栏 + 三条使用口径）与 **§7 前提 D / E**（净收益、`fork` 反噬的实测推导）。
> **建立**：2026-10-11（轨道 1 ① 落地：**子代理授权 + 三条护栏**）。状态：**生效**。
> **适用对象**：主会话、域会话；**子代理本身不适用**（见第一节最后一条）。
> 本文件是**一句话规则的唯一落点**；`dispatch-template.md` 只放指针、不复述。

---

## 一、授权范围（出处：提案 §2.1）

- **主会话**与**域会话**都可以在**自己会话内**派子代理，工具就是 `subagent` / `subagent_fork` / `workflow`。
- 派子代理**不再需要**主会话批准——这是对早年"不让会话私自拉子代理"的**有意反转**。
- ⛔ **子代理无权再派子代理（写死）**：不管用 `subagent` 还是 `workflow`，**父会话这一层就封死**，不商量、不留口子。
- ⚠️ **反转的代价**：当年的禁令是**有意为之**（有事故记录）。所以下面第二节三条护栏**必须与授权同时执行**，不是可选建议。

## 二、三条护栏（出处：提案 §2.1）

### 护栏 ① 分工不重叠

- 子代理**共享 cwd、无 worktree 隔离** ⇒ 并行子代理**必须职责不重叠**，否则互相覆盖。
- **并行派发时必须逐个写清各自的写文件清单**（谁写哪几个文件，一张小表即可；没写清就是没派好，不许"你们自己看着办"）。
- 先例：2026-08-27「共享工作区互切分支」。

### 护栏 ② 唯一写者不放松

- 子代理**不得写** `PROJECT.md` / `KNOWLEDGE.md` 总纲 / 域文档。
- 这些仍由**对应写者**写：`PROJECT.md` 与总纲＝主会话；域文档＝该域会话（该域唯一写者）。
- 子代理只写自己被派的那部分产出（代码 / 报告 / 测试）；跨域条目**交回父会话层**，别自己往总纲里塞。

### 护栏 ③ 汇报不算证据

- 子代理说"做完了"**不算完成**。验收必须落到 **落盘 + commit + 达成报告** 三样。
- 父会话必须**自己核对**：文件真在、commit 真在、报告里的文件清单与实际改动对得上。
- 先例：子代理报告与实际不符（LICENSE 缺口，靠核对才发现）；并行产出期间 `git add -A` 竞态夹带。
- ⇒ 并行产出期间，父会话**不要**跑笼统的 `git add -A`；按每个子代理报的**写文件清单逐个 add**。

## 三、三条使用口径（出处：提案 §2.1，实测推导见 §7 前提 D / E）

1. **`fresh` 优先，`fork` 例外**（前提 E）：`fork` **不是**减污染——它**继承父会话已完成的轮次**（带着同样的污染、还多一份上下文）。只有"**短任务且需要父会话的推理链**"才用 `fork`（KV cache 能命中父前缀，首步便宜）；其余一律 **`fresh` + 定向背景**。
2. **粗门槛**（前提 D）：**要读 3 个以上文件、或需多轮试错**的活才值得派子代理；一眼能改的活派了反而亏（冷启动 + 交代背景是固定开销）。
3. **并发天花板三条**：①本机资源（本地模型 / CPU 推理 / 生图——体系已记"转写期间不并行跑本地 LLM 与生图"）②共享 cwd 的写冲突 ③git 分支冲突。⇒ 并发只用在"**读多写少、职责不重叠、不撞本机资源**"的活上。

## 四、派发前自检（照这份清单逐条打勾）

- [ ] 这活**要读 3+ 文件、或需多轮试错**吗？不是就自己干。
- [ ] 用 `fresh` 还是 `fork`？除"短任务 + 需父推理链"外，一律 `fresh`。
- [ ] 要并行多个子代理吗？**每个的写文件清单**都写清了吗？职责真的不重叠、不撞本机资源吗？
- [ ] 会不会碰到 `PROJECT.md` / `KNOWLEDGE.md` 总纲 / 域文档？会碰就不派，交回**对应写者**。
- [ ] 验收标准写成"**落盘 + commit + 达成报告**"这三样了吗？
