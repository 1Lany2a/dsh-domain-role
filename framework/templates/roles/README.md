# templates\roles\ — 机读角色任务书（体系通用层）

> **这是什么**：每个「会话角色」一份任务书，**机器读**（bootstrap / 域桥按格式渲染成首条消息）＋ **人也能读**（就是一段干净的开场词）。
> **为什么有它**：`templates\会话开场提示词.md` 是「人复制粘贴」的载体，靠人不漏段；本目录把同一件事变成**插件能读的唯一源** ⇒ 用户不用再粘贴，AI 也不会因为漏粘一段而跑偏（2026-10-18 ⑥⑩ 组拍板 **P4＝A**）。
> **两者的关系**：本目录**不取代**提示词文件里的「设计理由」与「粘贴仪式」；提示词文件降级为「人读说明 ＋ 兜底粘贴版」，**内容以本目录为准**。改角色口径先改这里。

## 格式（schema 1，插件按此解析）

```markdown
ROLE: <role-id>
SCHEMA: 1
SLOTS: <槽位1>, <槽位2>
---

## 角色
一段话：这是什么角色、管什么、不管什么。

## 开场
可直接作为新会话**首条消息**的开场白（第一人称对 AI 说）；槽位写 {槽位名}。

## 规则
- 一条一行，3~6 条
```

**解析约定（实现方照此写，别自创）**

| 约定 | 说明 |
|---|---|
| 头块 | 文件开头到第一条 `---` 行；每行 `KEY: value`；键只有 `ROLE` / `SCHEMA` / `SLOTS` |
| 段 | `## 角色` / `## 开场` / `## 规则`，按 `## ` 切；**只认这三段**，其余段落忽略 |
| 规则段 | 每行以 `- ` 开头为一条；其他行归入上一条或忽略 |
| 槽位 | `{名字}`，**只能**用 `SLOTS` 里声明过的名字；未声明的按字面保留 |
| 渲染 | 输出纯文本：`【角色】…` ＋ 换行 ＋ `【开场】…` ＋ 换行 ＋ `【规则】` ＋ 每条一行 `- …`（**纯文本**，不依赖 markdown 结构） |
| 缺失 | 角色文件不存在／三段缺段 ⇒ **如实报 `missing-role-template`**，不许现编任务书 |

## 通用层 vs 项目特定层（别混读）

- 本目录＝**体系通用层**：任何项目都能用，内容只讲角色与流程。
- 项目根 `ROLES.md`（模板 `templates\ROLES.md.template`）＝**项目特定可选层**：某项目自己的人员/口令/特殊约定；**不存在时流程照样完整可用**。
- ⇒ 本目录的每个文件顶部都不写项目特定内容；要写项目特定约定，写进那个项目的 `ROLES.md`。

## 维护

- 改一个角色的口径：**先改这里**，再回看 `templates\会话开场提示词.md` 的对应段是否要同步（它现在是兜底粘贴版）。
- 新增角色：文件名＝`<role-id>.md`，并回本文件上表加一行。
- 不动 `{体系根}` 硬编码：一律写 `{体系根}`（换机只替换一个前缀）。
- **唯一例外**：知识库在 `{知识库}\`（**不在 `{体系根}` 下**），按固定路径写、不做槽位化（`system-main.md` 里那一处就是这样，别改成 `{体系根}\..\dsh\knowledge`）。
