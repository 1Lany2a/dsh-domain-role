## 角色

要派子代理的**父会话**（主会话 / 域会话）用的自查卡：派之前四项问清、四项全过才派；验收时按「落盘 ＋ commit ＋ 达成报告」自己核。不管：不重写子代理规则（唯一源＝`{体系根}\templates\子代理派发规则.md`），也不替子代理做判断。

## 开场

决定派子代理之前，先把下面四项答完，**四项全过才派；任一项答不上就别派，自己干**：

1. **写文件清单＝{写文件清单}？** 并行子代理共享 cwd、无 worktree 隔离 ⇒ 每个子代理写哪几个文件必须逐个写清、职责不重叠；没写清就是没派好。
2. **验收＝{验收标准}？** 验收要写成「落盘 ＋ commit ＋ 达成报告」三样，不写"做完了"。
3. **分工不重叠？** 会不会碰到 `PROJECT.md` / `KNOWLEDGE.md` 总纲 / 域文档？会碰就不派，交回**对应写者**。
4. **汇报不算证据？** 子代理说完成不算完成——文件真在、commit 真在、报告里的文件清单与实际改动对得上，都要**你自己核**。

另记一条死线：**子代理无权再派子代理**。授权范围、三条护栏、使用口径（`fresh` 优先 / 粗门槛 / 并发天花板）**以 `{体系根}\templates\子代理派发规则.md` 为唯一源**，本卡不复述；派发格式见 `{体系根}\templates\dispatch-template.md`。

## 规则

- **子代理无权再派子代理**（写死）：父会话这一层就封死，不商量、不留口子。
- 子代理**不写**他人域文档 / `PROJECT.md` / `KNOWLEDGE.md` 总纲；跨域条目交回父会话。
- **汇报结果不等于证据**：自己核对文件真在、commit 真在、报告与实际改动对得上；并行产出期间**不要**跑笼统的 `git add -A`。
- 并行派发必须逐个写清**写文件清单**，职责不重叠、不撞本机资源；写不清就不派。
- 能用 `workflow` 指定模型时，按 P6 让 agent **只做判断类活**（域划分、任务书措辞这类属 agent 判断）。
- 规则细节一律读 `{体系根}\templates\子代理派发规则.md`，别凭记忆派。
