# 会话协作框架（概念模型 · 不含技术选型）

> **定位**：这份文档只回答"我们要怎么组织会话之间的协作"——**身份、拓扑、权限、消息、生命周期**。

## 一、一句话

**把"会话"当成人来管：有身份、有岗位、有在任与离任；消息是请求，不是命令。**

## 二、本体：两层同构

**"同构"的含义**：两层都有**换届、交接、在线 / 离线 / 终结**。于是有两条直接推论：

1. **主会话也会换届**。新主会话面对一批**已经存在**的域会话，要做的是**认领**，不是重建；认领依据＝**域名册快照**（从使命库 + 索引派生，不新建台账）（"在任"不在此列，见 §十 裁定 2026-10-10）。
2. **交接要两个粒度**：**项目级**与**域级**。
3. **载体可以换，身份不换**：窗口关了，**域还在**，只是暂时不可达。

## 三、拓扑：星形（已定）

```
跨域消息一律经主会话：   域 A ──▶ 主会话 ──▶ 域 B
```

选它、而不是网状，三个理由（按权重）：

1. **协议最精简**——一种地址、一条路由。网状需要另定直连权限、冲突仲裁、可见性规则。
2. **状态集中**——"谁在线、谁是哪个域"只在主会话一处维护，好推理、好调试。
3. **域是长期稳定的划分，跨域通信本应低频**。若两个域频繁通信，**更可能是域边界画错了**，该拆该合。

**两层星**：每个项目一个中心；跨项目通信 ＝ 项目主会话 ↔ 项目主会话，**仍然是星形**。

**唯一硬伤 ＝ 单点**：主会话换届 / 崩溃 / 关窗 ⇒ 跨域通信全断。
**兜底**：换届交接包**必须包含**「**在途跨域通信**」＋「**域名册快照**」（**域名册快照＝域清单**；**当前负责人 + 在线状态 ＝ 在任声明**）。

## 四、权限层次：人 > 主会话 > 域会话

**域会话对域负责，不对主会话负责**；主会话是**建立者 / 交接者**，不是"上级"。

| 主会话**能做** | 主会话**不能做** |
|---|---|
| 立域、拆域、终结域 | 替域会话做**域内**决策 |
| 开域会话窗口、指定负责人 | 替域会话写域文档、署域的名 |
| 发起交接、移交在途事项 | 越过负责人**直接指挥其子代理** |
| 项目级协调、升级仲裁 | **覆盖用户直接下达的指令** |

> 主会话拿到的这一组权力统称**人事权**——**管人，不管业务**。

**人的最高权限（三条，写死）**：

1. 人可直接开 / 关任何窗口，**不经主会话**；
2. 人**可否决**主会话的立域 / 交接决定；
3. 人可直接对任意域会话下指令，**优先级高于主会话**。

> ⚠️ 这套"人事权"**不违反**既有的**主会话铁律**（"主会话只统筹、派发、合并，绝不直接改代码"）——立域 / 开窗 / 交接**都不是动手改代码**。
> 但**必须在活文档里显式列出来**，否则将来会有人拿老铁律来驳。

## 五、负责人模型

- **一对一是不变量**：一个域**同时只有一个负责人**。
- **同域多在线 ＝ 违规状态，不是容错**。发现就**报警**，**不"挑一个投"**。
- **并发 ≠ 多负责人**：并发需求由**负责人派子代理**承担（见第六节）。
- **在任声明**：判定"某域是否在线"**≠** "某个窗口开着"，而是"**哪个域会话当前被授权为该域负责人、且在线**"——**需要显式声明**，不许靠猜。

> **裁定（2026-10-09）**：本节的一对一不变量为**用户拍板口径**；`templates\dispatch-template.md` 原「同域最多 2 个窗口」的配额句**已作废**，同域并发改由负责人派**子代理**承担（定义登记在 `templates\术语表.md`）。

## 六、子代理的定位

- 子代理是**负责人派的临时工**，**不是域的代表**。
- 因此：**对外发言、写域文档、做承诺，仍由负责人署名**。
- 主会话**不越过负责人**直接指挥它。

> 这一条同时解决了"并发"：**要并行就在域内派临时工，而不是再开一个域会话**。

## 七、消息

- **语义**：跨域消息默认是**请求 / 通知**，**不是指令**——接收方是**另一个负责人**，不是下属。
- **方向**：**两条并存**——域 → 主会话（回报）、主会话 → 域（转达）。
- **格式（至少含）**：来自哪个域 / 哪位负责人 · 何时 · **通知还是请求** · **是否要求回复** · 关联哪个**使命编号**。

## 八、生命周期

> **状态模型（2026-10-14 改口径）**：**两个轴 ＋ 一个生命周期**——**事实轴 在线 / 离线**（宿主给、**只读**）＋ **政策轴 活动 / 已暂停**（**人给、可逆**）＋ **生命周期 在用 / 已终结**（`release` 写墓碑）。**给你（人 / AI）看的是两者合成的五种派生状态**：
- **「在线」＝权力与责任的在线，不是“能不能说话”**（用户 2026-10-18 澄清）：**退役／离线的会话仍可被人打开对话、也仍能主动发消息**（实测：已退役的会话照样能收发）；所谓“在线”只表示**它有活 Agent、能承担在岗责任、可作默认投递目标**。⇒ 判“这个域有没有人管”看的是**在任声明 ＋ 在线**，不是“窗口还能不能收发消息”；反过来，**离线／已终结 ≠ 失联**，只是不该再往那儿派活。

| 派生状态 | 事实轴 | 政策轴 | 消息怎么处理 |
|---|---|---|---|
| **在线 · 活动** | 在线 | 活动 | 可投递 |
| **在线 · 已暂停** | 在线 | **已暂停** | **插件介导的投递被拦**：**不投但入落盘队列**（可 `withdraw_domain_message` 撤回）；`create` / `wake` 拒。压着它的可能**同时有多级**（四级 OR 安全闸，见下） |
| **离线 · 活动** | 离线 | 活动 | 默认**不排队**、明确报"**不可达**"；要送必须显式 `wake` 且**接线可解**，否则**拒绝拉活** |
| **离线 · 已暂停** | 离线 | **已暂停** | 同上，且**不被自动叫醒**——只有人显式 `set_domain_state(active)` 才尝试唤醒 |
| **已终结** | —— | —— | 不接收（`release` 已写墓碑） |

**政策轴（已暂停）＝四级，是一个 OR 安全闸（2026-10-14 随域桥 v0.4.2 补；口径成对出现，另一处＝`SYSTEM-OVERVIEW.md` §三 同名子节）**：

| 级 | 机器面字面量 | 键是什么 | 压住谁 |
|---|---|---|---|
| **域** | `domain` | `项目:域`（**要求域名册里有这个 key**） | 进出这个域的消息（**只关这扇门**） |
| **主**（单会话暂停） | `session` | **完整会话 id** | 这一条会话（进出都算；**不要求**在任声明） |
| **项目** | `project` | 项目名 | 该项目下的会话与域（**不要求**在任声明） |
| **全局** | `global` | 保留键 `*` | 所有（**需 `confirm:true`**；**不要求**在任声明） |

- **四级平级、不是父子**：**域与主是平级的两级**——域是"一个域的门"，主是"一条会话的门"；机器面字面量恰为 `domain | session | project | global`（中文文档/回执把 `session` 叫「主（单会话暂停）」）。
- **OR 安全闸**：**任一级按下即停、下级绕不过**——项目被暂停时，它下面**没被单独暂停的域照样被拦**；回执必须列出**全部**命中的级别（`stillPausedBy`）。
- **裸短名 + 册子里无声明 ⇒ 域级不参与 OR 判定**：域键＝`项目:域`，索引标注给不出项目；且域级暂停本来就要求有声明 ⇒ 该级"**结构上不存在**"，进 `unresolved` 的是**会话级与项目级**。
- **两端都查**：发送端（本会话 id ／ 本会话项目 ／ 全局）＋ 接收端（目标域 ／ 目标会话 ／ 目标项目 ／ 全局）。
- **恢复＝逐条重评 OR**：恢复某一级后，只重投"**现在不再被任何一级压着**"的排队消息；**仍被别的级压着的一律保持入队**，并如实报出**还被谁压着**。**判据＝drain 逐条重评 OR ＋ 有没有 `stillPausedBy`**，不是队列文件长什么样。
- **防误触**：只有 `global` 要 `confirm:true`（**缺则直接拒、一个文件都不写**）；`domain` 级**仍要求域名册里有这个 key**（2026-10-14 拍板的「承认现状」，**不是 bug**），`session`／`project`／`global` 三级**不要求**任何在任声明。
- **队列仍按「被投递目标自身的键」分片**（域⇒域键、会话⇒会话 id），**不按 scope 分片**；一条 pending 能不能投，只取决于它**目标当下**的 OR 判定。
- **域级暂停只关那扇门、不禁言整个会话**：被按下的是"这个域"，不是"开着它的这条会话"——它照样能收发别的消息。
- **域退役之后的暂停（2026-10-14 用户选「承认现状」；如实写、不圆）**：域被 `release` 终结后派生状态＝**已终结**（暂停轴失去意义），**但状态记录留在盘上**（墓碑专门记了「终结时仍处于暂停」）⇒ **同一个 key 日后被重新认领时，这条老暂停会复活**（往它投消息会**静默入队**）。**不许写成"暂停随之作废"**——代码没这么做（`release_domain` 只合并 `terminatedAt`、不清 `paused`）；要真作废只需 release 时顺手清 `paused`（一行改动，**未做、待用户改口**）。
- **状态（2026-10-14）**：域级（v0.4.0/v0.4.1）＝**已实现并真机验过**；四级（v0.4.2）＝**已真机验过**（2026-10-14 08:36–08:42 用户重启 dsh 后：session／project／global 三级均成立、OR 叠加、`global` 缺 `confirm` 连目录都不建、恢复＝逐条重评 OR、域级 5/5 零回归、drain 真投；主会话另做独立验收：发送端 `self-session` 闸／撤回／恢复／global 防误触复查）。
- **已知限制（2026-10-14，如实记账）**：① **项目级判定不查会话存档** ⇒「离线**且**无在任声明」的会话推不出所属项目，按「拿不到就不拦」处理并标 `unresolved`（即**项目暂停拦不住这类会话被 `wake` 叫醒**；投递本因离线被拒）② `release_domain` **未暂停时也恒带** `pausedScopes: []` / `pausedByScopes: []`（与 `claim_domain` 的「零键」不同——这是例外，别按"claim 的规则"读）③ 拦截回执里 `matchedBy` 在「**裸短名走索引标注**」这条路径上仍回 `'declaration'`（该值是兜底，**不代表真有声明**，别据此去找/认领那条声明）。④ **未真机验（如实）**：F1 那条 index-label 分支的**前置条件今天不存在**（唯一带标注的在线会话标 `asr`，而 `asr` 在册子里有声明 ⇒ 走 `declared` 分支）⇒ F1 主分支**只有代码级证据**（独立核验者阶段三 18/18 PASS），其**姊妹断言真机已过**（判不出 ⇒ 不拦但 `unresolved` 如实 2 条）；另未验：发送端 `self-project`／撤回边界（`not-owner`、`force`、已投递、未知 id）／降级路径（坏状态文件、坏队列行）／`global` 的"别人也发不出去"（需第二个在线会话）／暂停下 `claim`/`release` 仍允许／`force:true` 放行——逐条列在 `tixiweihu\projectlog\2026-10-14-域桥v0.4.2-四级暂停-真机核验.md` 末节。
- **诚实边界**：只管**插件介导**的路径——**人自己点开、宿主自己 resume 拦不住**（那正是用户要的「人工手动唤起」）；停机通知 `notifyPredecessor` 刻意绕开暂停闸（止损优先）。

- **派生状态永不落盘**：真值**分散在两个轴上**（**在任声明** ＋ **状态记录**），派生状态只是给人看的**合成结果**——别把它当第三个存储、也别写进任何台账。
- **暂停不改在任身份**：声明册里 `sessionId` 一个字节不动 ⇒ **换人 / 交接 ≠ 解暂停**。
- **暂停只拦"插件介导"的路径**（诚实边界）：**人自己点开、宿主自己 resume 拦不住**——那正是用户要的「**人工手动唤起**」。
- **交接 ＝ 负责人变更**，需**公告**；交接包含：未决事项、对外承诺、**在途消息**；**在线映射同步更新**。

## 九、与官方 agent team 的对照（为什么不是同一件事）

| | 官方团队 | 本框架 |
|---|---|---|
| 一等公民 | 会话 / 成员 | **域**（会话只是载体） |
| 拓扑 | 星形（经 Lead）+ **并发执行** | **星形**（并发走子代理） |
| 换届 | **不支持** | **两层都支持** |
| 身份寿命 | 随 Lead 的会话 | **随域** |
| 通信寻址 | 成员名 | **域**（再由机制解析"当前负责人是谁"） |

**关键判据（2026-10-09 修正；2026-10-18 再更正）**：官方团队给不了"域身份跨窗口存续"。⚠️ **原写法「根因是它的成员是 Lead 的子代理」是错的**——每个 teammate 是**独立会话／独立 Agent**（各有 inbox、可冷恢复、可互相发消息，只有 Lead 能创建／指派／打断）。真正的根因有两条：① **roster 与任务板的真值由 Lead 的会话日志拥有、Team 的身份绑在 Lead 的 Session 上** ⇒ Lead 一换届就等于换了一个 Team；② **单进程单工作区**（成员共享 cwd，无 worktree、无跨项目）。

> ⇒ 本框架的**红线**：**域会话必须是顶层会话，不能是子代理**。
> ⚠️ 注意判据是「**顶层 vs 子代理**」，**不是「谁开的」**——**主会话开出来的也可以**，只要是顶层。

## 十、边界（明确不做什么）

- **不做网状直连**——暂缓，等有**真实跨域消息样本**再定。
- **不做第二本台账**——域名册只从**使命库 + 索引**派生，不新建存储。
- **不把子代理当域的代表**。
- **不让主会话替域会话做业务决策**。

> **裁定（2026-10-10）**：本节的「不做第二本台账」**只约束"域清单"**——"有哪些域"仍从使命库 + 索引派生、不新建存储。但**"当前在任"（谁现在代表这个域）不属于可派生事实**：实测使命库 79/95 条无域标注且状态全 completed、近 24h 有活动的 15 个会话只有 3 个推得出域、`gui` 还推出两个"活"会话。故按 §五「需要显式声明、不许靠猜」，新增**一份极小声明** `{体系根}\_registry\domains.json`：**一行一个域、key＝`<项目>:<域>`、只存"当前在任"**，不存历史 / 任务 / 状态。**域清单仍是派生的"域名册"；这份新存储是"在任声明"，两者不是同一个东西。**

## 十一、实现方式不在本框架内（备忘）

本框架**不决定**：通道怎么实现（插件 / 人搬运 / 混合）、"真·开窗"能否做到、消息字段怎么填。这些是**前提与选型**，归 `提案\提案2026-10-09-会话互通与子代理.md` §七。

**已实测的三条线索**（只作备忘，**不构成选型**）：

1. dsh 的会话控制包**存在 `session.create`**（可创建 / 恢复会话并持写锁，争用返回 `session/writer-held`）⇒ "建会话"有依据；"GUI 里出现可交互顶层窗口"**未见证据**。
2. 官方投递用的是**类型化 `source` 字段** + 消息开头一个**可见前缀块** ⇒ "接收方能否分辨「会话投的」与「用户敲的」"**有现成答案可抄**。
3. 官方那条内部投递路径**只覆盖"自己的子树"**，且 `TeamId = Lead 的 SessionId` ⇒ **给"非自己子代"的会话投递，本机无先例**（这是最大的待验项）。

## 十二、子代理派发在体系里的定位（2026-10-11 加）

- **轨道 1、零插件兜底**：把子代理授权给**主会话与域会话**，不依赖插件、不需要重启 dsh（授权本身只改文档）。它是 `提案\提案2026-10-09-会话互通与子代理.md` **轨道 1** 的第一项，也是**轨道 2（域可达层）做不出来时的退路**。
- **现状**：委派（`subagent` / `subagent_fork` / `workflow`）**早就是主会话的常态做法**；本次只是把**同一份授权明确延伸到域会话**，并补上配套护栏——不是新造一套机制。
- **与第六节的分工**：第六节讲**子代理是什么身份**（临时工、不代表域、主会话不越过负责人指挥它）；本节讲**谁可以派、派之前要守什么**。两者不冲突。
- **规则的唯一落点**：`templates\子代理派发规则.md`（一页纸，可直接照抄执行）——含**授权范围**、**三条护栏**（分工不重叠 / 唯一写者不放松 / 汇报不算证据）、**三条使用口径**（`fresh` 优先 `fork` 例外 / 粗门槛 / 并发天花板三条）。**本框架不复述细节**。
- ⚠️ **这是一次有意反转**：早年"不许会话私自拉子代理"是有意决定、且**有事故记录**（共享工作区互切分支、子代理报告与实际不符）；因此**授权与护栏必须同时生效**，不得只取授权。
