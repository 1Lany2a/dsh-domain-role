## 三、核心机制

### 信息读取层级（🟢🟡🔴，2026-09-03 定）

> 体系所有机制的"元设计原则"：**内容放哪一层，决定它何时花 token、AI 何时知道它。** 新机制/新规则落地前先问"放哪层"。

- **🟢 开场自动读**（每会话固定注入，省不掉，尽量精简）：dsh 系统提示、`~/.dsh/AGENTS.md`（88 行，2026-09-03 瘦身）、会话记忆（USER.md/MEMORY.md）。
  - 想让 AI"每个会话一定知道"→ 只能放这层；但每多一行 = 每会话多花一点，**只放高频必备**。
- **🟡 半自动触发读**（AI 主动读，靠 skill/开场声明驱动，不需逐次指示）：项目需求时加载 `dsh-knowledge-base` skill（含三级会话/并发协议/工具箱/防熵守则）、改代码时加载 `vibe-audit-logger-lite`、开局读 INDEX 速查表（~30 行）、按关键词精读 aspects 文档、读项目 ROLES.md / PROJECT.md / KNOWLEDGE.md 相关段。
  - 想让 AI"做项目时自动记得"→ 放这层（写进 skill 或开场声明）。
- **🔴 手动指示读**（你说才读，AI 不知道存在，最省钱）：本文件 SYSTEM-OVERVIEW.md（交接文档）、`templates\` 全部模板（派发/体检/重构/提案时读）、knowledge 深层文档与 projects 复盘、各项目 `提案\`、`projectlog\` 日志报告。
  - 想让内容"需要时才查"→ 放这层，不读不花 token。

**防膨胀规则**：内容能放🔴就不放🟡，能放🟡就不放🟢；AGENTS.md 只许高频必备（低频工具箱已移入 skill"常备工具箱"节）；机制沉淀在总览只写 1~3 行引用 + 细节归模板（总览是目录不是全书）。**新增后半条（2026-10-01）**：🟢🟡 层**新增一条规则必须同时删掉或降级一条**（置换原则）——只讲"放哪层"挡不住内容越积越厚。教训：AGENTS.md 曾 139 行含低频内容（第一性原理/代码 review/上下文压缩），2026-09-03 瘦身至 88 行，三块移入 skill；2026-10-01 一次改动就往派发模板第 0 步塞进 757 字，靠自查才收回。

### 产物落位约定（`D:\dsh\Generated\` 的边界，2026-10-08 用户拍板）

> **一句话**：**被活文档引用的东西，不许留在 Generated**——资产住在**引用它的那份文档旁边**。
> **为什么（实测）**：**引用复杂度是真成本，体积不是**。一次资产搬迁造成 **25 条引用失效、跨 6 个项目**，其中 **2 条是高危活代码**（ASR 链路断）；30 天被写文件 **531 个里 273 个（51%）不在任何 git 仓库内**（**口径注（2026-10-13 加，D10）**：这个基数取自 **2026-10-08 的索引版本**；`README.md` §四 那行写的「30 天 380 个被写文件、176 个在 git 外 ⇒ `git blame` 只答 25%」是**同口径的另一次（更早）量测** ⇒ **两次不可直接比**；2026-10-10 `session-registry.mjs` v2.4.0 修掉「存档格式失明」后，同一口径已变成 **806 个**，而 **2026-10-13 23:29 刷新后同一行又是 702 个（git 仓库外 435）**——**这类数每次刷新都会变**（见 changelog 2026-10-10）⇒ **看覆盖率请用最新一次的数**，统一口径留清理期） ⇒ 引用只能靠文档里的路径，路径一动就断、`git blame` 帮不上忙。而"体积"早有答案：项目目录已到 **3.5 GB**，但它们的 `.git` 全在 **0.1~2.9 MB**——产物在目录里，进 git 的只有文本。

**1. 判定（三条命中任一即算"资产"）**：① 被**活文档**引用；② 明确**可复用**（脚本/工具/模板）；③ **不可再生**（备份/快照/交付物/原型证据）。三条都不命中 ⇒ 一次性产物，**可以留在 Generated，也允许被遗忘**。
**2. 落位（三层 + "领域的家"）**：
- 属于**明确项目** → **该项目目录内**（资产与引用同处一个归属，路径最短、最不易断）
- 属于**体系 / 跨项目共用** → `D:\dsh\tools\`（脚本）、`D:\dsh\backups\{skills,templates,tools}\`（备份/交付物/原型）、`{体系根}\`（文档/模板/任务卡）
- **什么都不属于**（一次性的中间件、探针输出、临时测试副本、编译缓存）→ **留 Generated**（或直接清）
- **"领域的家"**：跨项目共用的领域资产放一个**归属单一**的稳定目录（先例：`D:\bendibushu\asr\` ＝ asr 域的家）。**禁止**一个日期目录里混放多个来源的东西。
**3. 进 git**：产物**可以进项目目录**，但**一律不进 git**（走 `.gitignore`）；进 git 的只有文本类（md/脚本/配置）。二进制一旦进库就难移除。
**4. 搬迁留指针（两条并存、互不替代）**：旧目录放 **`MOVED-TO.md`**（给"直接去找文件的人"）+ **改活文档里的路径**（给"读文档的人"）。**历史叙述不改**（changelog/历史报告里的旧路径按规矩保留，必要时加一行"已迁至"）。
**5. 防再漏（机械，不靠记忆）**：扫描写进 `templates\entropy-check-template.md` 第 5 节，**体检/审查时顺跑**。根因就是"人工列清单"——这已是第二次漏（第一次是交接前才发现第 9 条）。

### 展示物落位与「生成物三问」（2026-10-15 用户拍板 A05）

> **一句话**：**凡是"做出来给你看的页面"，一律进 `{体系根}\_pages\`，并且它不是真值。**
> **为什么**：体系里已经出现 3 份手写 HTML（`待拍板清单.html`、`技术脉络.html`、`工程进度图.html`）。它们与 `_registry\` 里的索引/交接包**长得像但性质不同**——`_registry\` 是"机器与接手者读的派生视图"，`_pages\` 是"给人翻的成品"；混在一层就会被**误当成真值**（去改它、或拿它当依据）。**另（实测）**：手写页每份有 **6%（表格型）~17%（叙述型）** 的体积是内联外壳，且两份页**各自抄了一份近亲 CSS**（逐行完全相同的只有 **21.3%**）⇒ 外壳成本付了两遍。

**1. 目录**：`{体系根}\_pages\`（与 `_registry\` **平行**）。页面与它的数据同处这一层，**不散在项目目录里**；目录内自带 `README.md` 就地声明"不是真值"。
**2. 它不是真值**（整目录删掉不影响任何机制）：真值永远是——各 `PROJECT.md` 的 §下一步、`_registry\domains.json`（在任声明）、使命库、会话存档、各提案正文、`templates\*` 与本文件（机制正本）。**`_pages\` 里的东西只准读、不准当依据**。
**3. 不准手改渲染页**：每份展示物＝**一个数据文件**（唯一可编辑处）＋**一份渲染页**（产物；手改会被下次渲染覆盖）。改内容、改名都改数据文件。
**4. 生成物三问（2026-10-15 起，任何新增生成物都必须先答）**：
   - ① **谁是源**？——哪一份文件是可编辑的唯一处（其余都是它的渲染/投影）。
   - ② **怎么渲染**？——一条能跑的命令。**命令只印在该产物自己的页头**，本节**不复制**（同一口径写多处必烂）。
   - ③ **怎么看出旧**？——页头必须同时印「数据更新于 X」与「页面生成于 Y」；**数据比页面新 ⇒ 它是旧页**，重跑 ②。
   - 派生视图的判据（沿用）：**删掉它，重跑一次就能变回原样**。做不到这条，说明它偷偷藏了真值。
**5. 例外与迁移**：**别人的插件产物不搬**（`dev-dashboard\index.html` 必须留在其契约位置；`drawio` 已弃用）。**项目自己的**同类产物（如 `tixiweihu\工程进度图.html`）**先记账、待用户点头再并**（并时须同步它的引用：`.dashboard-ignore` / `CHANGES.md` 各一处）。
**6. 落地件**：渲染器 `tools\render-doc.mjs` ＋ 模板 `templates\doc-view\`；数据写成 `<名>.data.js`、渲染成 `_pages\<名>.html`。

### 三级会话协作（2026-10-01 起执行层＝域会话）
- **主会话（统筹）**：读 PROJECT.md + 知识库（只读 INDEX 速查表）→ 列方案 → 拆任务 → **合并分支 + 唯一写者更新 PROJECT.md / KNOWLEDGE.md 总纲**。保持短会话。**多一项"分发"职责**：每件活完成后判"这条结论影响哪个别的域"。
- **副会话（答疑）**：一个主题系列疑问（可多轮），换系列新开；优先本地模型。
- **域会话（执行，2026-10-01 起为默认形态）**：**一个窗口长期负责一个域**（＝该域**负责人**；**一个域只有一个负责人**——2026-10-09 裁定，并行由负责人在域内派子代理），里面一件件放使命——不再是"一任务一窗口"。
  - 使命名带域 `S##-<域>-<slug>`；`mission.mjs declare` → feature 分支执行 → `mission.mjs complete`（**5 段必填**）
  - **只写自己那份域文档** `KNOWLEDGE\<域>.md`（落笔前先重读）；不写 PROJECT.md、不写总纲
  - **寿命（2026-10-08 改口径：取消硬阈值，只留软信号）**：体量 **>500k** 或 域记录 **>14 天** ⇒ 索引打 ⚠，**软信号、不是换人开关**；正确处理是**先压缩**（手动/自动都算），压缩后仍大且该域还有多件活，再谈交接（把"试过但没走通的路"写进域文档）。**首轮实测（2026-10-08，项目乙）**：原 150k 硬线等价于"一域一使命"——gui/asr 两窗口都是第 1~2 轮就越线，与旧子会话机制无异；而压缩实测把单步成本从 \$0.0258 降到 \$0.0059（**−77%**）。依据：`tixiweihu\projectlog\2026-10-08-项目乙-domain-mechanism-eval.md`
  - **验收不放松**：落盘 + git 分支 + 达成报告一样不能少
  - **重启后动域会话 · 检查单（2026-10-13 加，F3；操作版见 `templates\dispatch-template.md` 同名节）**：① **存在 ≠ 在线**——重启后会话只是"在列表 / 在存档里"，**要有活 Agent 才算在线**（旧会话常要被人点一下或被 resume 才活）；② **重启后先等几分钟**再决定换届（GUI 会陆续把窗口拉起来，早判＝误判）；③ **接管/换届前先确认或叫醒前任**（插件支持**静默叫醒** `ctx.agents.resume`：拉活、**不跑回合**）——⚠️ **但"叫醒"只解决"让它在线"，不解决"让它能干活"**：2026-10-13 真机，`resume` 拉活的会话**跑回合会在 100 ms 内崩**（`prompt variable "{{model}}" has no value for this assembly (section "deployment:persona-prefix")`）、**零产出**，而 GUI 自己拉起的会话同时段正常 ⇒ **给离线会话派活要走 `create_domain_session`（宿主建的新会话装配完整、能跑）或让人在 GUI 点开它**，别指望 resume 之后派活；**`wake='probe'` 永远发现不了这个坑**（probe 不跑回合）；④ **在任 ≠ 可达**（声明里在任，不等于消息送得到）。**硬事实（2026-10-12 查实）**：**静默投递 `inject` 不是耐久队列**——**未读的入队消息在 dsh 退出/重启时被整体取消**（实测 2026-10-12 23:45:48 三个不同会话的待读注入**在同一秒全部 `canceled`**）⇒ **跨会话派活要么用 `followup`（真唤醒、有成本），要么先落盘再重投**。

### 「已暂停」政策轴与四级暂停（域 / 主 / 项目 / 全局，域桥 v0.4.2）— 2026-10-14

> **口径成对出现**：本节 ＋ `会话协作框架.md` §八「生命周期」是这件事的**两个唯一源**，**两处口径必须一致**，改一处必须同改另一处。状态模型详解（五个派生状态那张表）在 `会话协作框架.md` §八，本节只写口径。

- **两个轴 ＋ 一个生命周期**：**事实轴 在线／离线**（宿主给、**只读**）＋ **政策轴 活动／已暂停**（**人给、可逆**；工具 `set_domain_state`）＋ **生命周期 在用／已终结**（`release_domain` 写墓碑）。对外一律给五种**派生状态**（`在线·活动`／`在线·已暂停`／`离线·活动`／`离线·已暂停`／`已终结`），**派生状态永不落盘**。
- **「在线」＝权力与责任的在线，不是“能不能说话”**（用户 2026-10-18 澄清）：**退役／离线的会话仍可被人打开对话、也仍能主动发消息**（实测：已退役的会话照样能收发）；所谓“在线”只表示**它有活 Agent、能承担在岗责任、可作默认投递目标**。⇒ 判“这个域有没有人管”看的是**在任声明 ＋ 在线**，不是“窗口还能不能收发消息”；反过来，**离线／已终结 ≠ 失联**，只是不该再往那儿派活。
- **四级、域与主平级**：`domain`（域；键＝`项目:域`）／`session`（**主**＝单会话暂停；键＝**完整会话 id**）／`project`（项目；键＝项目名）／`global`（全局；保留键 `*`）。机器面字面量就是这四个，中文文档/回执把 `session` 叫「**主（单会话暂停）**」。
- **OR 安全闸（下级绕不过）**：**任一级按下即停**——项目被暂停时，它下面**没被单独暂停的域照样被拦**；回执必须列出**全部**命中的级别（`stillPausedBy`）。**两端都查**：发送端（本会话 id ／ 本会话项目 ／ 全局）＋ 接收端（目标域 ／ 目标会话 ／ 目标项目 ／ 全局）。
- **恢复＝逐条重评 OR**：只重投"**现在不再被任何一级压着**"的消息；**仍被别的级压着的一律保持入队**，并如实报出**还被谁压着**。**判据＝drain 逐条重评 OR ＋ 有没有 `stillPausedBy`**，不是队列文件长什么样。
- **防误触**：`set_domain_state(scope='global', …, confirm:true)`——**缺 `confirm` 直接拒、一个文件都不写**；其余三级不要求。`domain` 级**仍要求域名册（在任声明）里有这个 key**（＝2026-10-14 拍板的「承认现状」，**不是 bug**）；`session`／`project`／`global` 三级**不要求**任何在任声明。
- **三条最容易写歪的边界**：① **域级暂停只关那扇门**（进出这个域的消息不通）——**不禁言整个会话**，它照样能收发别的消息；② **队列仍按「被投递目标自身的键」分片**（域⇒域键、会话⇒会话 id），**不按 scope 分片**；③ 只有**人**显式 `set_domain_state(active)` 才尝试唤醒离线目标——**暂停的域不会被别人自动叫醒**。
- **域退役之后的暂停（2026-10-14 用户选「承认现状」，如实写、不圆）**：域被 `release_domain` 终结后派生状态＝**已终结**（暂停轴失去意义），**但状态记录留在盘上**（墓碑专门记了「终结时仍处于暂停」）⇒ **同一 key 日后被重新认领时，这条老暂停会复活**（往它投消息会**静默入队**）。**不许写成「暂停随之作废」**——代码没这么做（`release_domain` 只合并 `terminatedAt`、不清 `paused`）；要真作废只需 release 时顺手清 `paused`（一行改动，**未做、待用户改口**）。
